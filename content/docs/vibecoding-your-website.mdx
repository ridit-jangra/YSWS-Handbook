Soooo not everyone wanna create a website from scratch and its kinda valid, creating a YSWS website is not easy at all, if its a simple landing then its ok but if u wanna build the whole dashboard, login flow, shop and everything in 1 website then it becomes complicated and vibe-coding is totally justified (unless you wanna ship your YSWS website into another YSWS, thats another case, in this case you have to follow the 30% AI-usage rule), but if you're not submitting it to any other YSWS then the 30% AI-usage rule does not apply :).

Ok now we know we can vibecode your websites, how?

## How to properly vibecode the website
First of all, don't just blindly believe all the AI code, it can contain security vulnerabilities so check the code yourself before pushing to production, and give claude or any other agent the `orchard mcp`, its a really good way to let claude get context of your database and other stuff.

### Adding orchard mcp to your agents or code editor

> Only do this step if you're sponsored and your sponsor gave you orchard access, if not then skip this step.

#### Claude
Add as a remote MCP server in Claude.ai settings

Go to Settings -> Connectors, scroll to the bottom and click Add custom connector, then enter the URL below. You'll be prompted to sign in with your Orchard account to authorize access.

Server URL<br/>
`https://mcp.k.hackclub.dev`

#### Claude code
Add to your project's `.mcp.json` or Claude Code settings

Claude Code supports remote MCP servers with OAuth. Add the following to .mcp.json in your project root, or to your global Claude Code settings. You'll be prompted to authorize on first use.

`.mcp.json`
```json
{
  "mcpServers": {
    "orchard": {
      "type": "http",
      "url": "https://mcp.k.hackclub.dev"
    }
  }
}
```
Or add it from the terminal with
```bash 
claude mcp add --transport http orchard https://mcp.k.hackclub.dev
```
then run `/mcp` inside Claude Code to authenticate.

#### VSCode
Add to your workspace or user MCP configuration

Open the Command Palette (Shift+Cmd+P) and run `MCP: Add Server`, or create `.vscode/mcp.json` in your project. VS Code will handle OAuth automatically.

`.vscode/mcp.json`
```json
{
  "servers": {
    "orchard": {
      "type": "http",
      "url": "https://mcp.k.hackclub.dev"
    }
  }
}
```
You can also add it to your user profile by running `MCP: Open User Configuration` from the Command Palette.


#### Cursor
Add to your project or global Cursor MCP configuration

Create `.cursor/mcp.`json in your project root for project-specific access, or `~/.cursor/mcp.json` for global access across all projects.

`.cursor/mcp.json`
```json
{
  "mcpServers": {
    "orchard": {
      "url": "https://mcp.k.hackclub.dev"
    }
  }
}
```
Cursor handles OAuth automatically. You'll be redirected to sign in on first use.

#### Token Authentication
For tools that don't support OAuth

If your MCP client doesn't support OAuth, you can authenticate with an API token instead. Create one in API Tokens, then pass it as a Bearer token in the Authorization header.

Tokens created on that page can only read. For an agent that deploys or changes things, create one with the CLI: `orchard auth token create --name agent --scope deploy` (or --scope exec to allow running commands in pods).

Configuration with token
```json
{
  "mcpServers": {
    "orchard": {
      "type": "http",
      "url": "https://mcp.k.hackclub.dev",
      "headers": {
        "Authorization": "Bearer orch_your_token_here"
      }
    }
  }
}
```

> These are taken from [Orchard's official docs](https://orchard.infra.hackclub.com/user/settings?tab=mcp)

### Deciding a theme
You can look at different YSWS websites in `Create your website` page, and you can ~~copy~~ take inspiration from them as well!!

Here is a prompt to get a theme for your YSWS pitch

> This prompt is generated by claude, i gave it a prompt i wrote and told it to refine it :) 

Original prompt
```text
https://ysws-handbook.vercel.app/docs/create-your-website read these docs and create a theme for my YSWS with pitch [insert pitch here] , take a look at all of the example YSWS images and create a perfect theme for my YSWS, give me backgrounds colors, fonts, accent colors, perfect framework to make it in, all the component libraries that the framework has and make a prototype landing using the same theme you generate as well, create a CSS file with all the colors in it and generate the website in sample-website/ folder and tell me what framework you used and what component libraries you used and everything, create multiple themes and i will choose 1 theme from all the ones you generate, create multiple landing pages like landing-1, landing-2, etc with all the themes in them.
```

The prompt u wanna use
```text
I'm building the website for a Hack Club YSWS (You Ship, We Ship) program.

**My pitch:** [PASTE YOUR PITCH HERE: what people build, what they get, who it's for]

The goal is NOT a clean, generic landing page. Good Hack Club YSWS sites feel
like a world: Re-dream is a hand-drawn dreamscape, Macondo turns "how it works"
into a branching fruit-trail map, Stardance shows real teen projects on a starry
timeline. If a page could belong to a different YSWS just by swapping the words,
it has failed.

## Step 1: Research (look, don't just read)
1. Read https://ysws-handbook.vercel.app/docs/tldr to understand what a YSWS is.
2. Read https://ysws-handbook.vercel.app/docs/create-your-website.
3. Open and actually LOOK at every example screenshot. They're at
   https://ysws-handbook.vercel.app/screenshots/<name>.png:
   Re-dream-hero, Wonders-hero, Live-hero, Alchemize-hero, Future-hero,
   Bento-hero, Pixl-hero, Pixl-what-is, Macondo-what-is, Macondo-how-this-works,
   Stardance-how-this-works-1, Stardance-how-this-works-2,
   Stardance-how-this-works-3, Stardance-FAQ.
   If you can't view images, stop and tell me instead of guessing.
4. For each one, write one line on what makes it memorable: the idea, not the colors.

## Step 2: Find 3 concepts, not 3 color schemes
Brainstorm at least 8 metaphors for the world my pitch lives in: a place,
object, ritual or game (for a shoe YSWS: a shoebox unboxing, a sneaker-drop
queue, a cobbler's workbench, a muddy trail map...). Pick the 3 strongest ones
that are most different from each other. Avoid the safe defaults (pixel/retro
arcade, tabloid/editorial, soft dreamy gradient, sticker-book) unless my pitch
really calls for one.

For each concept, define:
- **The metaphor:** what world the page is, and how every section lives in it
- **Colors:** hex values with roles; body text must meet WCAG AA contrast
- **Fonts:** from Google Fonts, chosen because they fit the concept
- **Signature moment:** one interaction or illustration only this pitch could
  have (e.g. laces you drag to tie, a shark that follows your cursor)
- **Art direction:** what the hero artwork is. Draw it as custom inline SVG
  (hand-drawn wobble, textures, characters), not icon packs or emoji. Where
  real art would be much better, leave a clearly marked placeholder that
  describes what an artist should draw.
- **Voice:** how the copy sounds, with 3 example lines

## Step 3: Pick the stack
Recommend one framework for a fast, mostly static site and explain why. List
the component, animation and icon libraries available for it, and say which
ones you'll actually use and why.

## Step 4: Build
If you have a frontend design skill available, use it. Create everything
inside `sample-website/`:
- `themes.css`: each concept's colors and fonts as CSS variables under its own
  selector, e.g. `[data-theme="concept-1"]`
- `landing-1`, `landing-2`, `landing-3`: one page per concept
- An index page linking to all of them

Every page needs the sections the handbook asks for: a hero (logo or wordmark,
punchline, call to action, nav), "What is this", "How this works", and an FAQ.
But each section must be told through the concept, and the pages must NOT
share a layout. These defaults are banned:
- Hero with text on the left and an illustration on the right
- "How it works" as 3 numbered cards in a row
- Project ideas as a 2×3 grid of cards
- A plain accordion FAQ
- A big "Ready to start?" banner right before the footer
Express them through the metaphor instead: "how it works" as a map, a receipt
or a level select; the FAQ as sticky notes, a chat, or a note tucked in a shoebox.

Copy must be real and specific to my pitch, written in the concept's voice, the
way a teenager would actually talk. No lorem ipsum and no filler like "Join our
community", "Start building today" or "Unleash your creativity". Always write
"Hack Club" exactly like that.

Pages must be responsive, with no horizontal scroll on mobile.

## Step 5: Critique, then redo
Screenshot every page at desktop and mobile widths and compare them with the
handbook screenshots. For each page ask:
- Could this be another YSWS's page with the words swapped?
- Does it look like a template or a typical AI-generated landing page?
- Is the signature moment actually there, and does it work?
If any answer is bad, redesign that page and check again.

## Step 6: Report back
- How to run it locally
- The framework and every library used, and what each one is for
- A table: concept, metaphor, palette, fonts, signature moment, page
- Which concept you'd pick for my pitch and why, plus what real art I should
  draw or commission to finish it

I'll pick one concept, and we'll build the real site from it.
```
